# 관계형 데이터베이스

관계형 데이터베이스(RDB, Relational Database)는  
데이터를 **행(Row)** 과 **열(Column)** 로 구성된 **테이블(Table)** 형식으로 저장하는 데이터베이스입니다.

## 특징

- 데이터 **무결성**과 **일관성**을 보장하기 쉽다.
- 데이터 **중복을 최소화**할 수 있다.
- 구조를 **표준화**하여 관리할 수 있다.
- 여러 테이블 사이의 **관계 설정**이 가능하다.

---

# 1. 구성요소

## 1) 테이블(Table)

데이터를 저장하는 기본 단위

- **행(Row)** : 하나의 데이터 단위
- **열(Column)** : 데이터의 속성

## 2) 스키마(Schema)

데이터베이스의 구조를 정의한 것  
테이블, 컬럼, 자료형, 제약조건 등의 정보를 포함함

## 3) SQL

관계형 데이터베이스를 조작하기 위한 언어

## 4) Key

각 행을 식별하거나 테이블 간 관계를 설정할 때 사용하는 값

---

# 2. 제약조건

제약조건은 데이터의 정확성과 일관성을 유지하기 위해 설정하는 규칙입니다.

## 대표 제약조건

- `PRIMARY KEY`
- `FOREIGN KEY`
- `UNIQUE`
- `NOT NULL`
- `CHECK`
- `DEFAULT`

---

# 3. 중복 제거와 키

관계형 데이터베이스에서는 **테이블을 분리하고 관계를 설정**하여 데이터 중복을 줄입니다.

다만  
**“키들은 중복되어서는 안 되고 NULL을 가질 수 없다”** 는 말은 모든 키에 해당하지 않습니다.

## 키 정리 표

|키 종류|의미|중복|NULL|
|---|---|---|---|
|Primary Key|각 행을 유일하게 식별|불가능|불가능|
|Foreign Key|다른 테이블의 기본키를 참조|가능|가능|
|Unique Key|중복을 허용하지 않음|불가능|DBMS에 따라 가능|

## Primary Key

- 각 행을 유일하게 식별
- 중복 불가
- NULL 불가

## Foreign Key

- 다른 테이블의 Primary Key를 참조
- 테이블 간 관계 형성
- 중복 가능
- NULL 가능

## Unique Key

- 값의 중복 방지
- Primary Key와 달리 여러 개 설정 가능
- NULL 허용 여부는 DBMS에 따라 다름

# 4. 정규화

정규화는 데이터 중복을 줄이고 이상 현상을 방지하기 위해 테이블을 분해하는 과정입니다.

## 제1정규화(1NF)

하나의 필드에는 하나의 값만 들어가야 한다.

## 제2정규화(2NF)

제1정규화를 만족한 테이블에서 **부분 함수 종속**을 제거한다.  
즉, 기본키의 일부에만 종속되는 속성이 없어야 한다.

## 제3정규화(3NF)

제2정규화를 만족한 테이블에서 **이행적 종속**을 제거한다.

### 이행적 함수 종속

A → B, B → C 일 때 A → C 가 성립하는 것

# 6. SQL 조건 사용 흐름

적어주신  
`select ~ where / join on / group by ~ having`  
내용은 **작성 순서**와 **실행 흐름**을 구분해서 보면 더 정확합니다.

## 1) 일반적인 작성 순서

SELECT  
FROM  
JOIN ... ON  
WHERE  
GROUP BY  
HAVING  
ORDER BY  
LIMIT

## 2) 의미별 정리

- `WHERE` : 그룹화 전에 개별 행 조건
- `JOIN ... ON` : 테이블 연결 조건
- `GROUP BY` : 그룹화
- `HAVING` : 그룹화 후 조건

## 3) 예시

SELECT dept, COUNT(*) AS cnt  
FROM employee  
JOIN department ON employee.dept_id = department.id  
WHERE salary >= 3000  
GROUP BY dept  
HAVING COUNT(*) >= 2  
ORDER BY cnt DESC;

# 7. SQL 트리거

트리거(Trigger)는 **특정 이벤트가 발생했을 때 자동으로 실행되는 객체**입니다.

## 트리거 발생 이벤트

- `INSERT`
- `UPDATE`
- `DELETE`

예:

- 데이터가 추가되면 로그 자동 저장
- 데이터가 수정되면 변경 이력 기록

---

# 8. 트랜잭션

트랜잭션(Transaction)은 여러 작업을 하나로 묶는 처리 단위입니다.  
모든 작업이 성공하면 반영되고, 중간에 오류가 나면 전체를 취소합니다.

적어주신 내용을 더 정확히 표현하면:

> 트랜잭션 안의 작업은 실행되지만, 최종적으로 `COMMIT` 되기 전까지 확정되지 않는다.  
> 오류가 발생하면 `ROLLBACK` 으로 이전 상태로 되돌릴 수 있다.

## ACID 특징

- **원자성(Atomicity)** : 전부 실행되거나 전부 취소
- **일관성(Consistency)** : 데이터 일관성 유지
- **격리성(Isolation)** : 동시에 실행되는 트랜잭션 간 간섭 방지
- **영속성(Durability)** : 완료된 결과는 영구 저장

## 상태

- **COMMIT** : 작업 결과를 최종 반영
- **ROLLBACK** : 작업 이전 상태로 복원

# 9. B-Tree

B-Tree는 데이터베이스에서 인덱스에 자주 사용되는 트리 구조입니다.

## 특징

- 데이터를 정렬된 상태로 저장
- 한 노드에 여러 값을 저장 가능
- 트리의 깊이를 낮게 유지
- 검색, 삽입, 삭제 성능이 좋음

즉, 데이터가 많아져도 깊이가 너무 깊어지지 않도록 하여 속도를 개선합니다.

---

# 10. 인덱스

인덱스(Index)는 데이터를 빠르게 찾기 위한 보조 구조입니다.

## 장점

- 검색 속도 향상
- `WHERE`, `JOIN`, `ORDER BY` 성능 향상

## 단점

- 별도 저장 공간 필요
- `INSERT`, `UPDATE`, `DELETE` 가 많으면 인덱스 갱신 비용이 발생

## 정리

- 조회가 많은 컬럼에 사용
- 중요한 검색 대상에 설정
- 너무 많이 만들면 비효율적일 수 있음

---

# 11. 뷰

뷰(View)는 `SELECT` 문을 기반으로 만든 **가상의 테이블**입니다.

- 실제 데이터를 따로 저장하지 않음
- 복잡한 조회문을 단순하게 재사용 가능
- 필요한 데이터만 보여줄 수 있음

즉, `SELECT` 결과를 테이블처럼 사용하는 개념입니다.

---

# 12. 서브쿼리

서브쿼리(Subquery)는 SQL 문 안에 포함된 또 다른 `SELECT` 문입니다.

즉,  
**SELECT 구문 안에서 SELECT를 사용하는 것**입니다.
