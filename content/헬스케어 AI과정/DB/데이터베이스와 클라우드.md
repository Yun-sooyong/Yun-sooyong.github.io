# Cloud와 Service 구조 정리

## 개요

클라우드 환경에서는 서버, 네트워크, 데이터베이스, 보안 설정을 클라우드 콘솔에서 관리하고,  
사용자는 네트워크를 통해 서버에 접속하여 웹 서비스나 데이터베이스를 운영합니다.

전체 구조는 다음 흐름으로 이해할 수 있습니다.

사용자  
→ 인터넷  
→ 공인 IP  
→ 방화벽  
→ 클라우드 내부 서버  
→ 웹 서버 / DB 서버  
→ 서비스 제공

---

# 1. 클라우드와 서비스 구조

## 기본 구성

- 클라우드 제공자: Google Cloud Platform(GCP), Microsoft Azure, Amazon Web Services(AWS)
- 클라우드 내부 자원:
    - 가상 서버
    - 스토리지
    - 네트워크
    - 데이터베이스
- 관리 도구:
    - 클라우드 콘솔
- 접근 방식:
    - SSH, Telnet 같은 원격 접속 도구
    - DB 접속 도구

## 핵심 개념

- 클라우드는 물리 서버를 직접 관리하는 대신, **가상화된 자원**을 필요한 만큼 제공하는 방식이다.
- 서버, 네트워크, 보안 규칙, 데이터베이스를 클라우드 콘솔에서 설정하고 운영할 수 있다.
- 일반적으로 웹 서버와 DB 서버를 분리하여 운영한다.

# 2. 클라우드 서비스 모델

클라우드 서비스는 보통 **IaaS, PaaS, SaaS**로 구분합니다.

## 2.1 IaaS (Infrastructure as a Service)

가상화된 인프라를 제공하는 서비스입니다.

### 제공 범위

- Virtualization
- Server
- Storage
- Network

### 사용자가 관리하는 영역

- OS
- Middleware
- Runtime
- Data
- Application

### 예시

- AWS EC2
- Azure Virtual Machines
- Google Compute Engine

### 특징

- 서버에 대한 제어권이 큼
- 설정 자유도가 높음
- 직접 관리해야 할 부분이 많음

---

## 2.2 PaaS (Platform as a Service)

애플리케이션 실행 환경까지 포함해 제공하는 서비스입니다.

### 제공 범위

- Virtualization
- Server
- Storage
- Network
- OS
- Runtime
- Middleware

### 사용자가 관리하는 영역

- Application
- Data

### 예시

- Google App Engine
- Azure App Service
- Heroku

### 특징

- 인프라 관리 부담이 적음
- 개발과 배포에 집중 가능

---

## 2.3 SaaS (Software as a Service)

완성된 소프트웨어를 인터넷을 통해 제공하는 서비스입니다.

### 제공 범위

- Virtualization
- Server
- Storage
- Network
- OS
- Runtime
- Middleware
- Application

### 사용자가 관리하는 영역

- Data 일부 또는 사용 설정 정도

### 예시

- Gmail
- Google Docs
- Slack
- Notion

### 특징

- 사용자는 설치보다 활용에 집중
- 관리 부담이 가장 적음

# 3. 네트워크와 프로토콜

## 3.1 네트워크 기본 개념

클라우드 서비스는 네트워크를 통해 연결됩니다.  
외부 사용자는 공인 IP를 통해 접속하고, 내부 서버들은 사설 IP를 사용합니다.

### IP 종류

- **공인 IP**: 인터넷에서 직접 접근 가능한 주소
- **사설 IP**: 내부 네트워크에서만 사용하는 주소

예:

- `192.168.8.0/24` 는 사설 IP 대역
- `/24` 는 서브넷 마스크를 뜻함

---

## 3.2 IPv4와 서브넷 마스크

### IPv4

IPv4는 32비트 주소 체계입니다.  
보통 점으로 구분된 4개의 숫자로 표현합니다.

예:

192.168.8.10

### 서브넷 마스크

IP 주소에서 **네트워크 부분**과 **호스트 부분**을 구분하는 값입니다.

예:

192.168.8.0/24

이 의미:

- 앞 24비트는 네트워크 주소
- 뒤 8비트는 호스트 주소

### /24 와 서브넷 마스크 관계

255.255.255.0 = /24

### 정리

- `192.168.8.0/24` 는 하나의 네트워크 대역
- 이 안에서 여러 장비가 사설 IP를 사용 가능

---

## 3.3 TCP와 UDP

사용자 메모에 `tcp`, `udp` 가 있는데, 같이 정리하면 다음과 같습니다.

### TCP (Transmission Control Protocol)

신뢰성 있는 연결형 프로토콜입니다.

### 특징

- 연결 지향
- 순서 보장
- 오류 확인
- 재전송 가능

### 사용 예

- 웹(HTTP/HTTPS)
- SSH
- 데이터베이스 연결
- 파일 전송

---

### UDP (User Datagram Protocol)

빠른 전송이 가능한 비연결형 프로토콜입니다.

### 특징

- 연결 과정이 없음
- 속도가 빠름
- 순서 보장 없음
- 재전송 없음

### 사용 예

- 실시간 스트리밍
- 게임
- DNS
- 음성/영상 통신

---

## 3.4 TCP와 UDP 차이

|항목|TCP|UDP|
|---|---|---|
|연결 방식|연결형|비연결형|
|신뢰성|높음|낮음|
|속도|상대적으로 느림|빠름|
|순서 보장|가능|불가|
|재전송|있음|없음|

# 4. Firewall

방화벽(Firewall)은 허용된 네트워크 트래픽만 통과시키고 나머지를 차단하는 보안 장치 또는 정책입니다.

## 역할

- 서버 접근 제어
- 허용된 포트만 열기
- 외부 공격 차단
- 내부 자원 보호

## 예시

- SSH 접속용 `22` 포트 허용
- 웹 서비스용 `80`, `443` 포트 허용
- DB 포트는 외부 전체 공개 금지

## 주의

- Telnet의 기본 포트는 `23`
- SSH의 기본 포트는 `22`
- MySQL의 기본 포트는 `3306`

# 5. 원격 접속 도구와 포트

## Putty

원격 서버 접속에 많이 쓰이는 도구입니다.

주요 용도:

- SSH 접속
- Telnet 접속 가능

### 관련 포트

- `22` : SSH
- `23` : Telnet

### 수정할 점

Telnet은 암호화되지 않아 보안상 매우 취약하므로,  
실무에서는 보통 **SSH만 사용**하고 Telnet은 거의 사용하지 않습니다.

## HeidiSQL

데이터베이스 접속 및 관리 도구입니다.

주요 용도:

- DB 접속

- SQL 실행
- 데이터 수정

### MySQL 기본 포트

- `3306`

# 6. OSI 7계층

OSI 7계층은 네트워크 통신 과정을 7단계로 나눈 참조 모델입니다.

## 계층

1. 물리 계층 (Physical)
2. 데이터 링크 계층 (Data Link)
3. 네트워크 계층 (Network)
4. 전송 계층 (Transport)
5. 세션 계층 (Session)
6. 표현 계층 (Presentation)
7. 응용 계층 (Application)

## 간단 정리

- **L1**: 실제 전기 신호, 케이블
- **L2**: MAC 주소, 스위치
- **L3**: IP 주소, 라우팅
- **L4**: TCP, UDP
- **L5~L7**: 세션, 데이터 표현, 애플리케이션 서비스

---

# 7. TCP/IP 4계층

실제 인터넷에서 더 자주 쓰는 모델은 TCP/IP 4계층입니다.

## 계층

1. 네트워크 액세스 계층
2. 인터넷 계층
3. 전송 계층
4. 응용 계층

## 대응 관계

|OSI 7계층|TCP/IP 4계층|
|---|---|
|응용 + 표현 + 세션|응용 계층|
|전송|전송 계층|
|네트워크|인터넷 계층|
|데이터 링크 + 물리|네트워크 액세스 계층|

# 9. DB 정리

## 데이터베이스(DB)

데이터를 저장하고 관리하는 시스템입니다.

서비스에서는 보통:

- 웹 서버
- 애플리케이션 서버
- DB 서버

를 역할별로 나누어 운영합니다.

---

## 9.1 관계형 DB

관계형 데이터베이스는 데이터를 **테이블 형태**로 저장하는 데이터베이스입니다.

### 특징

- 행(Row)과 열(Column) 구조
- 테이블 간 관계 설정 가능
- 중복 최소화
- 관리와 검색이 편리함
- 무결성 유지에 유리함

### 정리 문장 보완

`table을 분리시켜서 중복을 방지하고 관리를 편하게함`

→ 더 정확히 표현하면:

> 관계형 DB는 데이터를 여러 테이블로 나누고 관계를 설정하여 데이터 중복을 줄이고, 무결성과 관리 효율을 높인다.

---

## 9.2 PK, FK

### PK (Primary Key)

테이블의 각 행을 유일하게 식별하는 키

#### 특징

- 중복 불가
- NULL 불가

---

### FK (Foreign Key)

다른 테이블의 기본키를 참조하는 키

#### 특징

- 테이블 간 관계 형성
- 참조 무결성 유지

---

## 예시

### 회원 테이블

|회원ID(PK)|이름|
|---|---|
|1|Kim|
|2|Lee|

### 주문 테이블

|주문ID(PK)|회원ID(FK)|상품명|
|---|---|---|
|100|1|노트북|
|101|2|마우스|

여기서 `주문.회원ID` 는 `회원.회원ID` 를 참조합니다.

# 11. 수정해서 외우면 좋은 문장

## 클라우드

클라우드는 서버, 스토리지, 네트워크 같은 IT 자원을 인터넷을 통해 필요한 만큼 제공하는 서비스 방식이다.

## TCP

TCP는 연결형 프로토콜로, 신뢰성 있는 데이터 전송을 보장한다.

## UDP

UDP는 비연결형 프로토콜로, 속도는 빠르지만 신뢰성 보장은 약하다.

## 서브넷 마스크

서브넷 마스크는 IP 주소에서 네트워크 부분과 호스트 부분을 구분하는 값이다.

## 방화벽

방화벽은 허용된 포트와 접근만 통과시키는 보안 정책 또는 장치이다.

## 관계형 DB

관계형 DB는 데이터를 테이블로 나누고 관계를 설정하여 중복을 줄이고 관리 효율을 높이는 데이터베이스이다.

## PK / FK

- PK는 각 행을 유일하게 식별하는 키이다.
- FK는 다른 테이블의 PK를 참조하여 관계를 형성하는 키이다.
