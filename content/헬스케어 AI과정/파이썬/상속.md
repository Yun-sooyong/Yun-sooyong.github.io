# 상속 

기존 클래스(부모/슈퍼 클래스)의 속성과 메서드를 새로운 클래스(자식/서브 클래스)가 물려받아 재사용하거나 확장하는 객체 지향 프로그래밍 기법

### 특징 
- 상위 클래스는 `부모(Parent)`, 하위 클래스는 `자식(Child)`으로 부름 
- 자식 클래스는 부모 클래스와 공통되는 부분을 가짐
- 코드 중복 방지를 위해 보통 Tree(계층) 구조를 가짐 
- 연산자 오버로딩을 Object를 상속받아 재정의(overriding) 하는것으로 해결 

## 단일 상속(Inheritance)

단 하나의 부모를 가지는 상속 

## 다중 상속(multiple inheritance)
여러개의 상속을 받는 것 

하지만 상속을 받다보면 `다이아몬드 문제`가 발생 할 수 있다 
- 부모A를 상속받은 B,C 클래스가있다면 B,C 를 같이 상속받은 D는 중복되는 기능이 존재하게 된다 
- 파이썬은 중복이 발생할 시 먼저 상속 받은 클래스를 우선한다
- C / 자바는 단일 상속만 존재하고 `Interface`를 사용해서 다중상속 구현

## 포함(Component) 과 상속(Inheritance)

### 포함 
포함은 **클래스를 확장하는 개념**

현대적인 프로그래밍에서는 주로 포함을 사용한다 
부모 클래스를 상속받아 부모 클래스의 기능을 그대로 사용하는것 

### 포함과 상속의 차이

|   |   |   |
|---|---|---|
|구분|상속 (Inheritance)|포함 (Composition/Aggregation)|
|관계 정의|Is-A (~은 ~이다)|Has-A (~은 ~을 가지고 있다)|
|개념|기존 클래스를 확장하여 새로운 클래스를 만듦|기존 클래스의 인스턴스를 자신의 멤버로 가짐|
|결합도|매우 높음 (부모 변경 시 자식에 큰 영향)|낮음 (부품을 갈아끼우듯 유연함)|
|코드 재사용|부모의 기능을 그대로 물려받음|필요한 기능을 가진 객체를 생성해서 사용|
|설계 변경|컴파일 시점에 관계가 결정되어 변경이 어려움|런타임에 다른 객체로 교체 가능하여 유연함|
|대표 예시|포유류(부모) - 강아지(자식)|자동차(전체) - 엔진(부분)|

  
## 순수추상클래스

추상 함수(abstract)들이 모여있는 클래스 

### 특징
- 추상 클래스를 상속받으면 무조건 오버라이딩 해야함 
- 표준화된 틀을 제공해서 프로그램의 내용을 보호하면서 확장성을 유지할 수 있음 
- 순수추상클래스는 반드시 상속을 받아 재정의 하지 않으면 사용할 수 없다
- 유지보수가 쉬워짐 
- `@abstract` 데코레이터를 사용해서 연산자 오버라이딩을 지정해줄 수 있다 
    


### static과의 차이

|   |   |   |
|---|---|---|
|구분|static (정적)|abstract (추상)|
|핵심 개념|공통된 것 (공유)|미완성된 것 (설계도)|
|메모리 할당|프로그램 시작 시 자동 할당|자식 클래스가 인스턴스화될 때 할당|
|호출 방법|클래스명.메소드() (직접 호출)|자식 클래스에서 구현 후 객체로 호출|
|상속/오버라이딩|오버라이딩 불가 (재정의 의미 없음)|반드시 오버라이딩(구현) 해야 함|
|목적|유틸리티, 공통 데이터 관리|표준화된 틀 제공, 강제 구현|

## 디자인 패턴(Design pattern)

- `팩토리 메서드 패턴 (Factory Method)`: 객체 생성을 직접 하지 않고, 부모 클래스에서 객체 생성을 위한 인터페이스(메서드)를 정의한 뒤 자식 클래스에서 구체적인 생성 로직을 결정

- `어댑터 패턴 (Adapter)`: 상속을 통해 기존 클래스의 인터페이스를 다른 클래스가 기대하는 형식으로 변환하여, 호환되지 않는 객체들이 함께 작동하게 도움

- `템플릿 메서드 패턴 (Template Method)`: 부모 클래스에서 전체적인 알고리즘의 뼈대를 정의하고, 구체적인 단계는 자식 클래스에서 오버라이딩하여 구현하도록 강제하는 패턴

- `책임 연쇄 패턴 (Chain of Responsibility)`: 동일한 인터페이스를 가진 객체들을 체인 형태로 연결하여, 요청을 처리할 수 있는 객체를 만날 때까지 전달

- `믹스인 패턴 (Maxin)`: 특정 기능을 제공하는 작은 클래스들을 조립하듯 상속받아 기능을 확장하는 방식
