# 웹 프로그래밍 정리  
  
## 웹의 기본 구성 요소  
  
웹은 **클라이언트(Client)** 와 **서버(Server)** 가 통신하면서 동작한다.  
  
- **클라이언트**: 사용자의 브라우저  
- **서버**: 요청을 처리하고 결과를 응답하는 시스템  
- **통신 방식**: 주로 **HTTP/HTTPS**  
- **전송 데이터**: HTML, CSS, JavaScript, 이미지, JSON 등  
  
흐름은 다음과 같다.  
  
1. 브라우저가 서버에 요청(Request)을 보낸다.  
2. 서버가 요청을 처리한다.  
3. 서버가 응답(Response)을 반환한다.  
4. 브라우저가 응답 내용을 해석(Parsing)하고 화면에 렌더링(Rendering)한다.

# HTTP와 HTML  
  
## HTTP (HyperText Transfer Protocol)  
  
HTTP는 웹 브라우저와 웹 서버가 데이터를 주고받기 위한 **통신 규약(Protocol)** 이다.  
  
### 특징  
- **무상태(Stateless)**: 이전 요청 상태를 기본적으로 기억하지 않는다.  
- **요청/응답(Request/Response)** 구조  
- 주로 다음 메서드를 사용한다.  
  - `GET`: 데이터 조회  
  - `POST`: 데이터 전송  
  - `PUT`: 데이터 수정  
  - `DELETE`: 데이터 삭제  
  
### HTTPS  
- HTTP에 **보안(SSL/TLS)** 이 추가된 방식  
- 암호화된 통신을 제공한다.

## HTML (HyperText Markup Language)  
  
HTML은 웹 페이지의 **구조와 의미**를 정의하는 마크업 언어이다.  
  
### 특징  
- **Tag 기반 언어**  
- 문서의 구조를 표현한다.  
- 브라우저는 HTML 텍스트를 파싱하여 **DOM 트리**를 생성한다.  
  
### 예시  
```html  
<!DOCTYPE html>  
<html>  
<head>  
  <title>예제</title>  
</head>  
<body>  
  <h1>Hello</h1>  
  <p>문단입니다.</p>  
</body>  
</html>
```

### 중요한 점

- HTML은 **화면의 뼈대와 의미**를 담당한다.
- HTML 자체는 프로그래밍 언어가 아니라 **마크업 언어**이다.
- 동작 로직은 주로 JavaScript가 담당한다.

## CSS

CSS(Cascading Style Sheets)는 HTML 요소의 **스타일과 레이아웃**을 정의한다.

### 역할

- 색상, 폰트, 크기
- 여백, 정렬
- 테두리, 배경
- 애니메이션, 전환 효과
- 반응형 웹 디자인

### 예시

h1 {  
  color: blue;  
  font-size: 24px;  
}

### 중요한 개념

#### 1) 선택자(Selector)

HTML 요소를 선택한다.

- 태그 선택자: `p`
- 클래스 선택자: `.box`
- 아이디 선택자: `#title`
```css
p { color: red; }  
.box { border: 1px solid black; }  
\#title { font-weight: bold; }
```
#### 2) 클래스(class)와 아이디(id)

- **class**: 여러 요소에 공통 스타일 적용
- **id**: 문서 내에서 고유한 요소 식별

#### 3) 박스 모델(Box Model)

모든 HTML 요소는 박스 형태로 렌더링된다.

구성:
- content
- padding
- border
- margin

#### 4) 레이아웃

중요한 CSS 레이아웃 방식:

- `display: block`
- `display: inline`
- `display: inline-block`
- `flex`
- `grid`

특히 현대 웹에서는 다음이 중요하다.

- **Flexbox**: 1차원 정렬
- **Grid**: 2차원 레이아웃

#### 5) 반응형 웹

화면 크기에 따라 다른 스타일을 적용한다.
```js
@media (max-width: 768px) {  
  body {  
    font-size: 14px;  
  }  
}
```

## JavaScript

JavaScript는 웹 페이지의 **동작과 상호작용**을 담당하는 프로그래밍 언어이다.

### 역할

- 이벤트 처리
- 서버와 비동기 통신
- DOM 조작
- 데이터 검증
- 애니메이션 제어

### 예시
```js
document.querySelector("button").addEventListener("click", function () {  
  alert("클릭됨");  
});
```

### 중요한 점

- HTML은 구조
- CSS는 표현
- JavaScript는 동작

즉, 세 기술은 서로 역할이 다르다.

## 렌더링(Rendering)

브라우저는 서버에서 받은 HTML, CSS, JavaScript를 해석하여 화면에 출력한다.

### 기본 과정

1. HTML 파싱 → **DOM 트리 생성**
2. CSS 파싱 → **CSSOM 생성**
3. DOM + CSSOM 결합 → **Render Tree 생성**
4. Layout 계산
5. Paint
6. Composite

### 정리

- **DOM**: 문서 구조
- **CSSOM**: 스타일 정보
- **Render Tree**: 실제 화면 출력용 구조

---

## DOM과 BOM

## DOM (Document Object Model)

DOM은 HTML 문서를 객체 구조로 표현한 것이다.

### 특징

- 트리(Tree) 구조
- JavaScript로 접근 및 수정 가능
- 브라우저가 HTML 문서를 파싱하여 생성

### 예시

document.getElementById("title").innerText = "변경된 제목";

### 주의

- 최상위 객체는 일반적으로 **`document`**
- 사용자의 원문에 있는 “documents가 최상위”는 보통 **`document` 객체가 문서를 대표한다**고 정리하는 것이 정확하다.

---

## BOM (Browser Object Model)

BOM은 브라우저 자체를 제어하기 위한 객체 모델이다.

### 대표 객체

- `window`
- `location`
- `history`
- `navigator`
- `screen`

### 예시

console.log(window.innerWidth);  
console.log(location.href);

### DOM과 BOM 차이

- **DOM**: 문서(HTML)를 다룸
- **BOM**: 브라우저 자체를 다룸

## GUI 프로그래밍과 웹 프로그래밍

GUI(Graphical User Interface) 프로그래밍은 사용자가 **그래픽 요소를 통해 상호작용**하도록 만드는 방식이다.

### 웹에서의 GUI 구성 요소

- 버튼
- 입력창
- 체크박스
- 라디오 버튼
- 드롭다운
- 테이블

## 이벤트 기반 프로그래밍

웹 프로그래밍은 대표적인 **이벤트 기반(Event-driven)** 프로그래밍 구조이다.

### 이벤트(Event)란?

사용자나 시스템이 발생시키는 사건

예:

- 클릭
- 키보드 입력
- 마우스 이동
- 페이지 로드
- 스크롤
- 네트워크 응답 완료

### 이벤트 핸들러(Event Handler)

이벤트가 발생했을 때 실행되는 함수

button.addEventListener("click", function () {  
  console.log("버튼 클릭");  
});

### 콜백(Callback) 구조

이벤트가 발생하면 등록된 함수가 나중에 호출된다.

즉, 웹 프로그래밍은 **이벤트에 대한 callback 중심 구조**라고 볼 수 있다.

### 이벤트 큐(Event Queue)

브라우저는 이벤트와 작업을 큐에 넣고 순서대로 처리한다.

관련 중요 개념:

- Call Stack
- Event Queue
- Event Loop
- 비동기 처리

사용자의 원문에 있는  
“Event handler (Event Queue manager)”는  
정확히는 다음처럼 정리하는 것이 좋다.

- **Event Handler**: 이벤트 발생 시 실행되는 함수
- **Event Queue**: 처리 대기 중인 이벤트/작업이 저장되는 큐
- **Event Loop**: 스택과 큐를 확인하며 작업 실행을 조정하는 메커니즘

## Form 기반 프로그래밍

웹에서는 사용자의 입력을 받기 위해 **Form**을 사용한다.

### Form의 역할

- 사용자 입력 수집
- 서버로 데이터 전송
- 로그인, 회원가입, 검색, 주문 등에 활용

### 예시
```html
<form action="/login" method="post">  
  <input type="text" name="id">  
  <input type="password" name="pw">  
  <button type="submit">로그인</button>  
</form>
```

### 중요한 점

- Form은 단순 화면 요소가 아니라 **데이터 전송의 단위**
- `method`, `action`, `input name` 이 중요하다
- JavaScript와 결합하여 유효성 검사 및 비동기 전송(AJAX, Fetch)도 가능하다

### 보완할 내용

원문에 있는  
“테이블로 정보를 가져와서 form으로 화면을 올린다”는 일부 오래된 방식에 가까우며,  
현대 웹에서는 다음 방식이 더 일반적이다.

- 서버에서 데이터 제공
- JavaScript가 JSON 데이터를 받아 화면 갱신
- Form은 사용자 입력 처리
- Table은 데이터 표시용

즉:

- **Form**: 입력
- **Table**: 데이터 표시

## 태그 기반 프로그래밍

HTML은 태그 기반으로 문서를 구성한다.

예:
- `<h1>`: 제목
- `<p>`: 문단
- `<a>`: 링크
- `<div>`: 영역 구분
- `<form>`: 입력 양식

### 중요한 보완

원문의  
“html은 tag base로 태그를 전송하면 class 변환하여 사용”은 다소 부정확하다.

정확히는 다음과 같다.

- HTML은 **태그로 문서 구조를 표현**
- `class` 는 태그에 부여하는 **속성(attribute)** 중 하나
- 브라우저가 태그를 보고 DOM 객체로 변환
- CSS가 class, id, 태그 선택자를 이용해 스타일 적용

예:
```html
<div class="box">내용</div>
```

여기서:
- `div` 는 태그
- `class="box"` 는 속성

## 네트워크와 패킷

데이터는 네트워크를 통해 작은 단위로 나뉘어 전송된다.

## 패킷(Packet)

패킷은 네트워크에서 데이터를 나누어 전송하는 단위이다.

### 패킷 분할 이유

- 효율적인 전송
- 오류 발생 시 일부만 재전송 가능
- 여러 사용자가 네트워크를 공유하기 쉬움

### MTU (Maximum Transmission Unit)

한 번에 전송할 수 있는 최대 프레임 크기

- 일반적인 Ethernet MTU: **1500바이트**

### 일반적인 TCP/IP 구조

대략적으로 다음과 같이 생각할 수 있다.
- IP Header: 20 bytes
- TCP Header: 20 bytes
- Payload: 보통 최대 1460 bytes

즉:
- 1500 bytes = 20(IP) + 20(TCP) + 1460(payload)

- `<article>`

- 가독성 향상

## GPU 프로그래밍과 웹

원문에 있는 GPU programming은 웹과 직접 연결하면 다음과 같이 정리할 수 있다.

### GPU의 역할

- 그래픽 처리
- 렌더링 가속
- 애니메이션 성능 향상
- 2D/3D 처리

### 웹에서 관련 기술

- CSS 애니메이션 일부
- Canvas
- WebGL
- WebGPU

즉, 일반적인 HTML/CSS 작성 자체가 GPU 프로그래밍은 아니지만,  
브라우저는 렌더링 최적화 과정에서 GPU를 활용할 수 있다.
